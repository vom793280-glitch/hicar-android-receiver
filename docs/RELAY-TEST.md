# 路线 B 三机联调操作手册（Mate10 中继 + 华为发送手机 + 真车机）

目标：让无 BLE 广播的 8.1 真车机作为**真接收端**跑通投屏。中继手机只需搬 FE35/FE36 字节，
认证密钥、热点、画面全在车机。**不需要非华为手机当中继**——Mate10 即可（见下方说明）。

## 一、三台设备角色

| 设备 | 角色 | 装什么 | 关键配置 |
|---|---|---|---|
| Mate10（USB 连） | 中继机（有广播） | 最新版 APK | 诊断页进"12. 进入中继转发"，填车机蓝牙地址 |
| 华为手机（发画面） | 发送端 | 系统 HiCar，无需装 | 开蓝牙+WLAN，正常搜车机、输连接码 |
| 真车机 8.1（无广播） | 真接收端 | 最新版 APK（**需手动装，车机连不了电脑**） | 全部用界面操作：诊断页开"11. 中继隧道（车机端）"→ 首页开始连接 → 用"导出诊断报告"取日志 |

## 二、为什么 Mate10（华为机）能当中继

之前担心华为机的 `com.huawei.nearby` 抢 FE35/FE36，实测证明这个担心不成立：
- 我们的 App 和系统 nearby 能在同一台华为机上**各自注册** FE35/FE36（实测端口 5 注册成功）。
- Android 蓝牙栈允许多个应用注册相同 UUID 的 RFCOMM 服务。
- 这台 Mate10 的 `nearby` 和 `instantshare`（会自动重开蓝牙的元凶）已 `disable-user`（enabled=3）。
- Mate10 的 FDEE BLE 广播已验证能启动。

所以中继机用 Mate10 完全没问题，不必找非华为手机。

## 三、前置条件（必须全部满足）

1. **三台都装最新版 APK**：`dist/HiCarLab-0.12.0-android8.apk`（18:58 构建，含中继 FE35/FE36 双路监听修复）。
   - Mate10 已装（USB）。
   - **真车机连不了电脑**：把 APK 拷到 U 盘，插车机用文件管理器安装；或用车机浏览器/应用商店能访问的方式装。
     装完在诊断页标题确认版本是 `0.12.0`。
   - 华为发送手机不用装。
2. **中继机与真车机在系统蓝牙里预先配对一次**：
   - 这是两台你能物理接触的设备，手动配对不违反"首次发现"约束。
   - 配对后记下**真车机的蓝牙 MAC 地址**（中继要填这个）。
3. **中继机与真车机蓝牙都开着**，且互相在可发现状态。
4. **车机端能开热点**（车机自检确认过 2.4G 热点 + BSSID 有效）。
   - 注意：你说"车机 WLAN 和热点不能同时打开"。当前设计是车机开热点(AP)，手机连该 AP 后
     用 client IP 与车机通信，**不要求车机同时连别的 WLAN**，理论兼容。

## 四、操作步骤（按顺序）

### 步骤 1：真车机开隧道服务端
- 车机上打开 App → 设置与诊断 → 找到 **"11. 中继隧道（车机端）"** 按钮，点成 **"已开启"**。
- 回首页 → 点 **"开始连接"**。
- 此时车机**不广播**（中继代劳），进入等待隧道状态。日志应出现：
  ```
  隧道服务端已就绪（等待中继手机连接）；本机不直接广播，FE35/FE36 字节将由中继转发。
  ```

### 步骤 2：Mate10 启动中继
- Mate10 上 App → 设置与诊断 → **"12. 进入中继转发"**。
- 填真车机的蓝牙 MAC（如 `7E:34:46:00:00:E7`）→ 点 **"启动中继"**。
- **成功标志**（这是 0.10 修复的验证点）：日志出现**两行独立的**监听：
  ```
  FE36 等待华为手机连接...
  FE35 等待华为手机连接...
  ```
  如果只看到一行"中继已就绪：等待华为手机连接 FE35/FE36"汇总、没有这两行，
  说明装的是旧版，必须重装最新版。
- 还应看到：`中继 FE36 端口 N 已通过隧道告知车机`、`FDEE 广播已启动`。

### 步骤 3：华为手机发起连接
- 打开蓝牙 + WLAN，搜 HiCar 设备（会看到中继广播出来的车机）。
- 点连接 → 输入连接码（**连接码在真车机 App 首页显示**）。

### 步骤 4：判断成功
- 车机日志出现：`FE35 收到连接` → `FE36 收到连接` → `HiChain 认证成功` →
  `收到手机 TCP 连接` → `收到 H.264 数据帧` → `解码输出已提交视频窗口：N 帧`。
- 车机屏幕出现画面。

## 五、如果卡住，按这个顺序排查

1. **中继没有那两行 `FE35/FE36 等待...`** → 旧版 APK，重装。
2. **中继连不上车机隧道**（报 `连接车机隧道服务 ... IOException`）→
   车机端隧道服务端没开（步骤 1 没做），或两台没配对，或车机蓝牙地址填错。
3. **手机弹码但车机无 `FE35/FE36 收到连接`** → 手机连到了系统 nearby 而非中继；
   确认中继的两路监听都在（步骤 2）。
4. **认证成功但无 H.264** → 查手机是否连上车机热点、是否拿到 client IP；
   这是热点链路问题，不是中继问题（普通模式 18:05 已证明热点+投屏链路正常）。
5. **有 H.264 但无画面** → 解码/显示问题，与中继无关。

## 六之一、为什么两端日志不一样（角色分工）

同一个 APK，两种角色跑不同代码，日志文案与层次本就不同：

- **中继端**（RelayActivity，日志带 `[中继]` 前缀）：只搬 FE35/FE36 原始字节，**不解析内容**。
  所以只有传输层事件：`连接车机隧道服务`、`FE36 端口告知`、`FE35/FE36 等待华为手机连接`、
  `FDEE 广播已启动`、`开始双向转发`。它**不会**打印"认证成功"——看不懂字节内容。
- **车机端**（ReceiverEngine 隧道模式，无前缀）：跑完整协议栈，拿到字节后解析。
  所以有协议层事件：`隧道服务端已就绪`、`已从中继取得 FE36 端口`、`HiChain 认证成功`、
  `网络协商/凭据已发送`、`收到手机 TCP 连接`、`收到 H.264 → 解码 N 帧`。
  它**不会**打印"FE35 等待华为手机连接"——接手机的是中继。

结论：两份日志**互补**，不是重复。排查时——中继确认"字节在搬"，车机确认"协议走通"。
链路是 手机→中继→隧道→车机，哪段断就在那端日志停住：

| 现象 | 断点 | 看哪端 |
|---|---|---|
| 中继无 `FE35/FE36 等待...` 两行 | 中继没接手机（旧版 bug） | 中继 |
| 中继有 `开始双向转发`，车机无 `FE35 收到连接` | 隧道没送到车机 | 车机 |
| 车机有 `FE35 收到` 无 `认证成功` | 认证阶段 | 车机 |
| 认证成功但无 `收到 H.264` | 热点/网络 | 车机 |

日志的写法规矩（解释"为什么同一 App 两份日志看着不一样"）：

- `DiagnosticLog` 是**进程内全局单例**：整个 App 所有角色都往**同一份** `hicarlab-trace.txt` 追加，
  按时间戳排序，靠前缀区分。
- `RelayActivity`（中继角色）写的行**带 `[中继]` 前缀**；`ReceiverEngine`（车机角色）写的行**无前缀**。
- 因此：
  - 只跑中继的设备（如 Mate10）：日志全是 `[中继]` 行（隧道连接、FE35/FE36 等待、广播、双向转发）。
  - 只跑车机的设备：日志全是无前缀行（隧道服务端、认证、网络协商、H.264）。
  - **同一台设备先后开了车机开关又跑了中继**：两种日志会**按时间混排在一份文件里**——
    比如非华为机截图里 18:27 的无前缀 `FE35 控制帧/网络协商/热点移除`（车机角色），
    紧接着 18:30 的 `[中继]` 隧道连接（中继角色）。这不是异常，是同一 App 两个角色都跑过。
- 各设备的 trace 文件物理隔离（每台设备各自 sdcard），不会跨设备串；但**同设备内两个角色会混写**。

## 六、导出日志给我（车机连不了电脑，只能用界面）

- **Mate10（连 USB）**：可以用 adb 精确导出中继日志：
  ```
  adb -s D3H0217B29012266 pull /sdcard/Android/data/local.hicarlab/files/hicarlab-trace.txt
  ```
- **真车机（在车上、连不了电脑）**：只能用 App 界面：
  1. 设置与诊断 → 滚到底 → 点 **"导出诊断报告"**
  2. 系统会弹文件保存框，选个位置保存（如"下载"目录，文件名默认 `HiCarLab-report.txt`）
  3. 用手机拍照或把该 txt 文件传出来发我。
  4. **关键**：报告里要能看到时间从"开始连接"到卡住那一刻的日志。导出会自动停止当前测试，
     所以要在测试跑完/卡住后再导出。
- 如果车机导出后不方便传文件，**直接把车机屏幕上的诊断日志区域拍照发我也行**——之前你发的三张照片
  就是这么做的，能看清时间戳和关键行就够定位。
